# WireConform v0.1.0-beta.1

WireConform is a beta CLI for checking multipart requests produced by generated OpenAPI clients. It captures requests on loopback, compares their parts with expectations derived from the document's OpenAPI version, and returns a nonzero exit code for a detected conformance failure.

## Demonstration

The release includes a passing binary-and-text case and a regression case for the multipart Content-Type mismatch reproduced by Hey API 0.99.0. Run them from the extracted source archive:

```powershell
wireconform run examples/hey-api-positive.yaml --adapter hey-api
wireconform run examples/regression.yaml --adapter hey-api
$LASTEXITCODE
```

The first command passes. The regression command reports two `CONTENT_TYPE_MISMATCH` diagnostics and exits with code `1`; a test harness can pass by asserting that result.

Captured output from the pinned Hey API adapter:

```text

PASS binary-and-text (3 parts)

FAIL issue-4281-products-array (4 parts)
  CONTENT_TYPE_MISMATCH: Content-Type does not match for products part 1.
  CONTENT_TYPE_MISMATCH: Content-Type does not match for products part 2.

```

## Installation

Download and extract the source archive attached to this GitHub release. From the extracted project directory, install dependencies and link the CLI:

```powershell
npm ci
npm run build
npm link
wireconform adapters
```

WireConform is not published to npm in this beta. The project requires Node.js 22.18 or newer. Java 11 or newer and the official OpenAPI Generator CLI 7.26.0 JAR are required only for the `openapi-generator` adapter. Set `WIRECONFORM_OPENAPI_GENERATOR_JAR` to the JAR path; WireConform checks its pinned SHA-256 and reported version before use. The Hey API baseline uses `@hey-api/openapi-ts` 0.99.0 and TypeScript 5.9.3.

## Environments

The release candidate was locally verified on Windows with Node.js 24.15.0 and Temurin Java 11.0.32.1. The GitHub Actions workflow is configured for Windows and Ubuntu across Node.js 22.18, 24, and 26, but no hosted run has completed yet. macOS is not covered by the current CI workflow.

## Known limitations

- Multipart checks support OpenAPI 3.0.0–3.0.4 and 3.1.0–3.1.2, a documented subset of schema shapes, and local JSON Pointer references. See [conformance limits](../conformance.md).
- External references, nested multipart, streaming requests, arbitrary schema composition, security requirements, operation/path parameters, and several advanced encoding options are unsupported and reported explicitly.
- Generated SDK code runs with the current user's permissions. The loopback/network checks are defense in depth, not a sandbox; use only trusted specifications and fixtures.
- Adapter behavior is verified only for the documented pinned versions. The newer Hey API prerelease check is observational and is not a supported adapter version.
- Hosted GitHub Actions verification is pending the first authorized push to GitHub.
