# WireConform v0.1.0-beta.2

WireConform checks whether generated OpenAPI clients send multipart requests that match expectations derived from their OpenAPI document. It captures requests on loopback and returns a nonzero exit code when serialization does not conform.

## Demonstration

Install the pinned Hey API baseline in the WireConform checkout and run the committed regression fixture:

```powershell
npm ci
npm run build
node dist/cli.js run examples/regression.yaml --adapter hey-api
$LASTEXITCODE
```

Expected output from the verified Hey API 0.99.0 regression run:

```text
WireConform 0.1.0-beta.2 — postProductUploadDocument (POST /product/uploadDocument)
Adapter: hey-api 0.99.0
FAIL issue-4281-products-array (4 parts)
  CONTENT_TYPE_MISMATCH: Content-Type does not match for products part 1.
  CONTENT_TYPE_MISMATCH: Content-Type does not match for products part 2.
Result: FAIL
Report saved.
```

The command exits `1`. The two repeated `products` parts were captured as `text/plain`, while the OpenAPI 3.0.4 encoding declares `application/json` for each object item. This preserves the original PartProbe proof of concept as a regression case.

## Installation

Download and extract the source archive for this release, then run:

```powershell
npm ci
npm run build
npm link
wireconform adapters
```

WireConform is not published to npm. Node.js 22.18 or newer and npm are required. The Hey API 0.99.0 adapter uses the pinned baseline dependencies in the repository. OpenAPI Generator 7.26.0 requires Java 11 or newer and the official CLI JAR; set `WIRECONFORM_OPENAPI_GENERATOR_JAR` to that JAR. WireConform verifies its SHA-256 checksum and reported version before use.

## Upgrading from beta.1

Replace the beta.1 source checkout with the v0.1.0-beta.2 source archive, then run the installation commands above. No npm package is available. Avoid using beta.1 with private inputs in shared terminals or CI logs; the beta.2 fix prevents future diagnostic output from including parser excerpts or absolute paths, but it cannot remove output already recorded by beta.1.

## Environments

The hosted workflow covers Ubuntu 24.04 and Windows with Node.js 22.18, 24, and 26. CI uses Java 17; the adapter accepts Java 11 or newer based on its runtime version check. macOS is not covered by the current workflow.

## Supported generators and OpenAPI versions

| Adapter | Generator target | Verified version | Requirements |
| --- | --- | --- | --- |
| `hey-api` | `@hey-api/client-axios` | `@hey-api/openapi-ts` 0.99.0 | Node.js and the pinned generator/compiler dependencies |
| `openapi-generator` | `typescript-axios` | OpenAPI Generator CLI 7.26.0 | Java 11+ and the verified official CLI JAR |

The separately pinned Hey API prerelease comparison is observational and is not a supported adapter. Multipart expectations support OpenAPI 3.0.0–3.0.4 and 3.1.0–3.1.2 within the documented subset of schema shapes and local JSON Pointer references. See [conformance limitations](../conformance.md).

## Diagnostic privacy notice

The published v0.1.0-beta.1 could echo malformed YAML source excerpts and local paths in some errors. This beta replaces those messages with stable diagnostics: YAML errors expose only validated line/column coordinates, filesystem failures omit absolute paths, and unexpected exceptions use a generic message. Do not share beta.1 output from private inputs; its tag and source archive remain unchanged.

Reports omit request bodies, filenames, credential fields, and header values by default. They retain specification and fixture identifiers, including operation IDs, path templates, basenames, case names, and part names; Content-Type mismatch diagnostics include expected and captured media-type essences. Do not put secrets in those identifiers, and review reports before sharing.

## Security limitations

Generated SDK code runs in a child Node process with the current user's permissions. The loopback and network checks are defense in depth and do not sandbox generated code. Use trusted OpenAPI documents and fixtures, and do not run generated clients where they can access sensitive files or credentials.

## Known limitations

- Only the documented multipart/form-data subset and OpenAPI versions above are supported; unsupported constructs are reported explicitly.
- External references, arbitrary schema composition, nested multipart, streaming requests, security requirements, operation/path parameters, and some advanced encoding options are unsupported.
- macOS is not covered by the hosted CI matrix.
- Adapter behavior is verified only for the pinned versions in the support matrix.
- WireConform has not been published to npm.
